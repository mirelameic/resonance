# RESONANCE

Static archive site for discovering connections between creative works.
No backend, no build step, no accounts. See `README.md` for what it is
and how to run it. This file is implementation notes for whoever (human
or AI) touches the code next — the code itself carries no comments by
design; this is where the "why" lives instead.

## Never run git commands that change state

Read-only git commands (`git status`, `git diff`, `git log`, `git
show`, etc.) are fine to run freely. Never run one that changes repo
or working-tree state — `git add`, `git commit`, `git push`, `git
checkout`, `git reset`, `git stash`, and so on. The user runs all of
those themselves, whenever they decide to. Editing files is fine;
staging or committing them is not, even if the work is finished and
verified.

**One exception:** an implementer subagent executing one task of a
`superpowers:subagent-driven-development` plan may run `git add`/`git
commit` locally as part of that task (the skill's per-task review
relies on diffing commits) — never `git push` or anything that touches
a remote. This exception is scoped to that implementer role only; the
coordinating/interactive session (you, reading this outside that
narrow role) still never touches git beyond read-only commands.

## Do not add comments in code

Do not write `//`, `/* */`, or `<!-- -->` comments in any file in this
project (js, mjs, css, html, tests) — not even short ones, not even for
non-obvious logic. If something needs explaining for future work on this
project, add it here in `CLAUDE.md` instead (or in the PR/commit message
if it's tied to a specific change), and let names and structure carry
the rest. This applies to new code and to edits of existing code alike.

## Architecture

- `index.html` + `js/main.js` — shell, theme toggle, hash router bootstrap.
- `js/router.js` — `location.hash` <-> `{ view, params, query }`. Filter
  state lives in the query string (bookmarkable, back/forward works).
- `js/data.js` — the dataset. **Auto-generated by `scripts/sync-data.mjs`.
  Never hand-edit it** — it's overwritten wholesale on every sync run.
- `js/filters.js` — pure faceted filtering for the Explore view.
- `js/similarity.js` — the connections engine.
- `js/render.js` — DOM rendering per view.
- `scripts/sync-data.mjs` + `scripts/lib/*` + `scripts/sources/wikidata.mjs`
  — the data pipeline (see below).

## Product decision: no country/medium gets special treatment

The archive is global by design — every country and (eventually) every
medium (music, film, literature, visual art, added gradually) is fetched
through the same generic path. There used to be a hardcoded Brazil quota
in the sync (a separate guaranteed bucket per decade); it was deliberately
removed. Don't reintroduce per-country or per-region special-casing in the
sync or in the copy — if a country/medium is underrepresented, that's a
sourcing-strategy problem to solve generically, not with a hardcoded QID.

## Data pipeline gotchas (Wikidata / WDQS)

These were found the hard way, against the real public endpoint
(`query.wikidata.org`) — a mocked-fetch unit test cannot catch most of
them, since it only asserts query *text*, never real SPARQL evaluation
semantics. Re-verify against the live endpoint if you touch the query
shape in `scripts/sources/wikidata.mjs`.

- **Earliest-date pinning**: a multi-dated item (original release,
  re-releases, restorations) must be bound as `MIN(?date) AS ?firstDate`,
  never a plain `SAMPLE`, or you get an arbitrary date instead of the
  earliest one.
- **Decade range filter must live in `HAVING`, after `GROUP BY`** — not
  in a per-row `WHERE` `FILTER`. An earlier attempt used
  `FILTER NOT EXISTS { ?item wdt:P577 ?earlierDate . FILTER(?earlierDate
  < ?date) }`, which looks correct but silently deleted every multi-dated
  item from every bucket (verified live against Q1054036 "Central
  Station", which has 6 `P577` values and vanished from the corpus
  entirely instead of being pinned to 1998-01-16).
- **User-Agent header must be pure ASCII.** An em dash in the header
  broke every single fetch call in production — `fetch` headers are
  ByteStrings and can't carry arbitrary Unicode.
- **Build the query URL with `encodeURIComponent` manually**, not
  `URLSearchParams` — the latter encodes spaces as `+`, and
  `decodeURIComponent` doesn't turn `+` back into a space.
- **Retry only on 429/502/503/504** (Wikidata's shared endpoint is often
  under load). A malformed query returning 400 will just fail again —
  don't retry it.
- **`countryQid` filtering**: `SAMPLE(?countryLabel)` aggregates over
  *every* `P495` value on the item, so for a co-production it can report
  the wrong country. When a query is restricted by `countryQid`, prefer
  the deterministic `?filteredCountry` binding over the sampled
  `?country`. Real bug this fixed: Clandestine Childhood / La Playa DC /
  On the Road were all reported under their *other* co-production
  country despite being fetched by a country-filtered query (finding #3
  of the original data-sourcing review).
- **`image` (P18)** already resolves to a full, pre-percent-encoded
  Commons `Special:FilePath` URI — just upgrade `http://` to `https://`,
  don't re-encode it.
- **Recent-films window** (`queryRecentFilms`) is year-granular, not a
  fixed rolling window: current year + 1 previous year in the second
  half of the year, + 2 previous years in the first half. That's
  deliberate, not a bug.

## Dataset conventions

- **Id uniqueness**: title + year is not a reliable key across a large
  real-world corpus (remakes, common titles collide) — every id has the
  source QID appended, lowercased.
- **Sentinel/fallback values**: when Wikidata data is sparse, the mapper
  (`scripts/lib/mapWikidata.mjs`) emits placeholders — `'Unknown'`
  (creator), `'Uncategorized'` (genre/style), `'Storytelling'` (themes),
  `'Evocative'` (mood). `js/similarity.js` has a sentinel guard
  (`SENTINEL_VALUES`) so two unrelated sparse works never score a fake
  match just because they share a placeholder string. If you add a new
  fallback value in the mapper, add it to that set too.
- **Per-medium facet exclusions** (`js/filters.js`): `FACET_EXCLUSIONS_BY_MEDIUM` is an
  exception-list keyed by tab id (`film`, `music`, `literature`, `visual-arts`) — it only
  declares which facet keys a medium *hides* from the Explore filter panel (today: film
  hides `movement`, since it's auto-derived noise there, not a curated taxonomy). A medium
  with no entry shows every facet by default, so adding a new facet key later doesn't
  require updating this map. `MEDIUM_TABS` is the tab list Explore renders from; the
  Visual Arts tab matches two `medium` values (`visual-arts` and `photography`) rather
  than one — see the "photography vs visual-arts" note in the schema (`VALID_MEDIA` in
  `test/data.test.js`).
- **Sync checkpointing** (`scripts/lib/syncState.mjs`): `recordBucketResult`
  is pure (never mutates the state passed in) and a bucket is marked
  exhausted the moment a query returns fewer rows than requested — that's
  WDQS's own "nothing more to page into" signal. A failed query never
  reaches this function at all (the caller only calls it after success),
  so a transient network/server error never advances or exhausts a
  bucket; the same offset is simply retried next run.
- **`periodReason` strings** in `js/similarity.js` all share a `"same
  era"` prefix on purpose — `pickUnexpectedConnection` matches on that
  prefix to detect a period-only (not-very-interesting) connection.

## Testing

- `npm test` runs every pure logic module under Node's built-in test
  runner — no dependencies. Covers `js/router.js`, `js/filters.js`,
  `js/similarity.js`, the `js/data.js` schema, and the whole sync
  pipeline (`scripts/lib/*`, `scripts/sources/wikidata.mjs`).
  `js/main.js`, `js/render.js`, `js/reveal.js` are DOM-touching and
  intentionally untested here.
- `test/mapWikidata.test.js` uses `wd:Q220741` ("City of God") as a
  live-verified fixture QID — `wd:Q186358`, the QID a prior fixture
  assumed, actually resolves to "1860 Atlantic hurricane season". If you
  add new Wikidata-based fixtures, verify the QID against the real
  endpoint before trusting it.
- Several tests are regression tests for specific bugs found during a
  real sync run (see the Wikidata gotchas above) — if one starts failing
  after a query-shape change, treat that as a sign the bug may be back,
  not as a test to loosen.

## Abandoned directions (don't redo without a reason)

- A hand-curated placeholder dataset — dropped once the Wikidata sync
  worked.
- TMDB as a data source — dropped once its commercial-use licensing
  terms became clear (Wikidata is CC0, free, no API key).
- TV/series support — removed; the dataset and schema are film-only for
  now, other media are added when actually implemented, not speculated
  about in code.
- A hardcoded Brazil representation quota in the sync — removed, see
  "Product decision" above.
